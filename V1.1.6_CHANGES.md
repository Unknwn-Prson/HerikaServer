## Fix: Simple Format Empty Message Marked as Parsed (CRITICAL)

### Problem

When using simple format, only the format marker appeared without the actual message.

**Example**:
- LLM output: `lovely) : pauses in her organization of the supplies...`
- What appeared in-game: `lovely`
- Missing: Entire message after the format marker

### Root Cause - Streaming Chunk Timing

**First streaming chunk** arrives with just format marker: `lovely)`

1. Parse with prefill: `(` + `lovely)` = `(lovely)`
2. Regex matches successfully:
   - mood: `lovely`
   - message: `` (EMPTY STRING!)
3. **BUG**: We marked as parsed even though message was empty
4. Set `_simpleFormatParsed = true`
5. Set `_simpleFormatMessageStart = 0`

**Second chunk** arrives with full text: `lovely) : pauses in her organization...`

1. Check: `_simpleFormatParsed` → TRUE (already marked!)
2. Skip parsing, go to incremental content branch
3. Check: `if (_simpleFormatMessageStart > 0)` → **It's 0!**
4. Return empty string
5. **Result**: No message output, only mood extracted

### Solution

Don't mark as parsed if the message is empty - wait for actual content:

```php
if ($parsed['found']) {
    // CRITICAL FIX: Don't mark as parsed if message is empty
    // First streaming chunk might have format markers but no message yet
    if (empty($parsed['message'])) {
        // Message not arrived yet, don't mark as parsed - try again next chunk
        return "";
    }

    // NOW safe to mark as parsed - we have actual message content
    $this->_simpleFormatParsed = true;
    // ... rest of processing
}
```

### How It Works Now

**Chunk 1**: `lovely)`
- Parse: mood=`lovely`, message=`` (empty)
- Check: `empty($parsed['message'])` → TRUE
- Return `""` WITHOUT marking as parsed
- `_simpleFormatParsed` remains FALSE ✓

**Chunk 2**: `lovely) : pauses in her organization...`
- `_simpleFormatParsed` is still FALSE, so parse again
- Parse: mood=`lovely`, message=`pauses in her organization...`
- Check: `empty($parsed['message'])` → FALSE
- Mark as parsed: `_simpleFormatParsed = true` ✓
- Set `_simpleFormatMessageStart` to message position ✓
- Return full message ✓

**Chunk 3+**: Buffer continues growing
- `_simpleFormatParsed` is TRUE
- `_simpleFormatMessageStart > 0` → TRUE
- Return incremental content normally ✓

### Edge Cases Handled

**Case 1**: Format markers with colon but no text yet
- Buffer: `lovely) : `
- Message: `` (empty)
- Returns `""`, waits for more data ✓

**Case 2**: Multiple format markers, incomplete
- Buffer: `lovely)(player)` (if expecting mood+listener+message)
- Message: `` (empty)
- Returns `""`, waits for more data ✓

**Case 3**: Message starts immediately without colon
- Buffer: `lovely)text here`
- Message: `text here` (has content)
- Processes correctly ✓

**After (v1.1.6)**: Full message appears correctly

## Technical Details

### Why This Bug Existed

The regex pattern `/^\s*\(?([^)]+)\)\s*:?\s*(.*)$/s` successfully matches:
- Input: `(lovely)`
- Groups: mood=`lovely`, message=`` (empty string captured by `(.*)`)

The `(.*)` at the end captures zero or more characters, so an empty string is a valid match. We need to explicitly check if the message has content.

### Why empty() Is The Right Check

- `empty("")` → TRUE (empty string)
- `empty("text")` → FALSE (has content)
- Works for all cases including whitespace-only strings after trim
