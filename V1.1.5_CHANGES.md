## Fix: Simple Format Fallback Stripping First Character (CRITICAL)

### Problem

When using simple format, only the first few characters appeared in-game instead of the full message.

**Example**:
- LLM output: `lovely) : pauses in her organization of the supplies...`
- What appeared in-game: `ovely`
- Missing: First character `l`

### Root Cause

The v1.1.4 fallback code tried to "strip the prefill" from the buffer:

```php
// WRONG - v1.1.4 fallback code
$bufferToReturn = $this->_usedPrefill ? substr($this->_buffer, strlen($this->_prefillContent)) : $this->_buffer;
```

**Critical Mistake**: The prefill was NEVER in `$this->_buffer`!

**How it works**:
1. API returns: `lovely) : pauses...` → stored in `$this->_buffer`
2. We add prefill temporarily: `(` + `lovely) : pauses...` = `(lovely) : pauses...` → used for regex parsing only
3. `$this->_buffer` still contains just: `lovely) : pauses...` (raw API response)

**What went wrong**:
- Fallback code did: `substr('lovely) : pauses...', 1)` (thinking it was stripping `(`)
- Result: `ovely) : pauses...` (stripped first character of actual message!)

### Solution

Return `$this->_buffer` directly without any stripping:

```php
// CORRECT - v1.1.5 fix
// CRITICAL FIX: Don't strip prefill from buffer - it was never included in $this->_buffer!
// The prefill is only added to $bufferToParse for regex matching, but $this->_buffer
// contains only what the API returned (e.g., "lovely) : pauses..."), NOT the prefill
$this->_lastReturnedLength = strlen($this->_buffer);
return stripReasoningTokens($this->_buffer);
```

## Technical Details

### Buffer vs BufferToParse

**Key Concept**: These are two different variables:

1. **`$this->_buffer`**: Raw API response
   - Example: `lovely) : pauses in her organization...`
   - This is what gets returned to CHIM
   - Never includes the prefill

2. **`$bufferToParse`**: Temporary parsing buffer
   - Example: `(lovely) : pauses in her organization...`
   - Used only for regex matching
   - Includes prefill prepended
   - Not stored, discarded after parsing

### Why Prefill Exists

The prefill `(` is sent to the API to encourage the LLM to output format markers:
- Without prefill: LLM might output `(mood) text` or just `text`
- With prefill `(`: LLM completes with `mood) text` → combined = `(mood) text`

The API doesn't return the prefill in its response - we already know what we sent.

### Why the Bug Happened

The v1.1.4 code assumed:
- Buffer contains: `(lovely) : pauses...`
- Need to strip: `(`
- Do: `substr(buffer, 1)`

Reality:
- Buffer contains: `lovely) : pauses...` (API response only)
- Stripped: First `l` of `lovely`
- Result: `ovely) : pauses...` ✗
