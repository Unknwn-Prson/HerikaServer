# Version 1.1.3 Changes - Max Cache Validation Fix

**Date**: 2025-11-12
**Version**: v1.1.3
**Previous**: v1.1.2

---

## Summary

This release fixes a UI validation bug that prevented users from saving large max_dialogue_cache values.

---

## Fix: Max Dialogue Cache Size Validation Limit

### Problem

Users couldn't save `max_dialogue_cache` values above ~200. The form would reject values like 500 or 1000, even though the backend had no such limit.

### Root Cause

HTML5 input validation:
```html
<input type='number' name='metadata[max_dialogue_cache]'
       min='30' max='200' step='1'>
```

The `max='200'` attribute caused browsers to reject higher values client-side before form submission.

### Solution

Changed HTML validation limit from 200 to 2000:

**Files Modified**:
- `ui/core/llm_connectors.php` line 481 (Profiles section)
- `ui/core/llm_connectors.php` line 1519 (Main LLM Connectors section)

**Change**:
```html
<!-- OLD -->
<input type='number' name='metadata[max_dialogue_cache]'
       value='93' min='30' max='200' step='1'>

<!-- NEW -->
<input type='number' name='metadata[max_dialogue_cache]'
       value='93' min='30' max='2000' step='1'>
```

### Tooltip Updates

Also updated tooltip text to reflect new range:
- **Old**: "(30-200)"
- **New**: "(30-2000). Recommended: 93-200."

### Impact

**Before**: Couldn't save values above ~200

**After**: Can save values from 30 to 2000

**Note**: Backend connector has no hardcoded limit - this was purely a UI validation issue.

## Known Recommendations

While the limit is now 2000, recommended values are:
- **93-200**: Most users (good balance of context vs cache size)
- **200-500**: Advanced users with longer conversations
- **500-2000**: Specific use cases requiring extensive history

Higher values mean:
- ✓ More dialogue context preserved
- ✗ Larger cache files
- ✗ Potentially higher API costs (depending on provider)
