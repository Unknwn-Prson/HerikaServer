## Version 1.1.4 (2025-11-12) - CRITICAL FIXES

### Critical Bug Fixes

**Bug #1: Profile Section Settings Not Saving (CRITICAL)**
- **Problem**: Connector settings in Profiles editor were silently discarded
- **Root Cause**: Used `metadata[...]` field naming instead of `meta_vis[...]`
- **Impact**: All connector settings in Profiles section non-functional
- **Fix**: Renamed 13 fields in Profiles section to use `meta_vis[...]` convention
- **Files**: `ui/core/llm_connectors.php` lines 429-494
- **Result**: Profile section settings now save correctly
- **Note**: Main LLM Connectors section was unaffected (already worked correctly)

**Bug #2: Simple Format Not Working (CRITICAL)**
- **Problem**: Simple format responses received but never appeared in-game or context
- **Impact**: Complete message loss when using Simple format (affected v1.0.19f and all v1.1.x)
- **Root Causes**:
  1. No fallback handling when parsing failed → empty string returned
  2. Regex required both parentheses → prefill case failed unpredictably
  3. Regex didn't handle optional colons → some LLM outputs failed
- **Fixes**: Cherry-picked from v1.0.20-22 Bug #6 & #8 (legitimate fixes):
  1. Added fallback handling (returns raw buffer when parsing fails)
  2. Made opening parenthesis optional in regex: `\(?` instead of `\(`
  3. Made colon optional after format markers: `:?\s*`
- **Files**:
  - `connector/openrouterjsoncached.php` lines 1035-1049 (fallback)
  - `connector/openrouterjsoncached_verbose.php` lines 1720-1742 (fallback with logs)
  - `connector/openrouterjsoncached_helpers.php` lines 540-545 (regex fixes)
- **Result**: Simple format now works with variations and graceful fallback

### Changed Fields (Profile Section)
All 13 connector setting fields in Profiles section renamed:
- `provider_caching`
- `dialogue_cache_uncached_count`
- `minimize_quality_prompt`
- `response_format`
- `include_mood_requirement`
- `include_listener_requirement`
- `include_actions_list`
- `include_target_requirement`
- `max_dialogue_cache`
- `custom_system_instruction`
- `custom_last_instruction`
- `verbose_logging`

### Files Modified
- `ui/core/llm_connectors.php` - Fixed Profiles section field naming
- `connector/openrouterjsoncached.php` - v1.1.3 → v1.1.4
- `connector/openrouterjsoncached_verbose.php` - v1.1.3 → v1.1.4
- `connector/openrouterjsoncached_helpers.php` - Fixed simple format regex

## Version 1.1.2 (2025-11-12) - CRITICAL FIXES

### Critical Bug Fixes

**Issue #2: Duplicate Memory Removal Timing (CRITICAL)**
- **Problem**: `removeDuplicateMemories()` was called AFTER cache markers were placed
- **Impact**: When duplicates were removed, array indices shifted, causing cache markers to move to wrong messages or be deleted entirely
- **Fix**: Moved `removeDuplicateMemories()` to run BEFORE cache calculations
- **Files**: `openrouterjsoncached.php` line ~506, `openrouterjsoncached_verbose.php` line ~663
- **Result**: Cache markers now stay stable on correct messages
- **Added**: Logging to track deduplication count

**Missing TEMPLATE_DIALOG Prompt (HIGH PRIORITY)**
- **Problem**: Dialogue template prompt completely missing from connector
- **Description**: The "Write HERIKA_NAME's next dialogue line" instruction was never inserted
- **Impact**: LLM missing roleplay instruction, minimize_quality_prompt setting not working
- **Fix**: Added TEMPLATE_DIALOG insertion in uncached section after last user message
- **Files**: `openrouterjsoncached.php` line ~524, `openrouterjsoncached_verbose.php` line ~703
- **Controlled By**: `minimize_quality_prompt` setting (enabled = short, disabled = verbose)
- **Result**: LLM now receives proper roleplay instruction

### Message Sequence Changes

**New final sequence**:
```
1. System prompt + format instructions (CACHED)
2. Dialogue history (CACHED)
3. Dynamic environment (UNCACHED)
4. Custom last instruction (UNCACHED, if enabled)
5. Last user message (UNCACHED)
6. TEMPLATE_DIALOG - roleplay instruction (UNCACHED) ← NEW
```

### Technical Improvements
- Added comprehensive logging for both fixes
- Commented out old duplicate removal calls with explanations
- Added cross-references between related code sections
- Both standard and verbose connectors updated

### Files Modified
- `connector/openrouterjsoncached.php` - v1.1.1 → v1.1.2
- `connector/openrouterjsoncached_verbose.php` - v1.1.1 → v1.1.2

**Files Modified**:

### Bug Fixes

**Gemini Cache Index Bounds Check**
- **Problem**: When `indexToCache == 0`, code blindly set it to 33 without checking array size
- **Impact**: Silent cache failures in early conversations
- **Fix**: Added bounds check - only use index 33 if array has 34+ elements, otherwise skip caching
- **Files**: `openrouterjsoncached.php` lines 538-550, `openrouterjsoncached_verbose.php` lines 749-773
- **Added**: Clear comments explaining Gemini's 32-token minimum requirement

## Feature Summary (All Versions)

### Caching Support
- **Anthropic**: Native cache_control markers with TTL
- **OpenAI**: Automatic caching (no markers needed)
- **Gemini**: Batch-based caching with minimum token requirements

### Response Formats
- **JSON**: Structured output with configurable fields
- **Simple**: Natural language with format markers like (mood)(listener)(action)(target)

### Configurable Fields
- Mood (emotional state)
- Listener (who NPC is speaking to)
- Actions (available game actions)
- Target (action target, required if actions enabled)

### Cache Configuration
- Uncached dialogue count (keep last N messages fresh)
- Max dialogue cache size (total cached messages, up to 2000)
- Custom system instruction (added to system prompt, cached)
- Custom last instruction (added near end, uncached)

### Quality Settings
- Minimize quality instructions (short vs verbose dialogue prompt)
- Response format toggles (mood, listener, actions, target)
- Provider-specific optimizations

## Known Limitations

### Current
- TEMPLATE_DIALOG assumes `prompts/dialogue_prompt.php` loaded by CHIM core
- Dynamic environment insertion position at count-2 (may not match all user expectations)
- Gemini formula behavior documented but not fully verified (see GEMINI_CACHING_FUTURE_ANALYSIS.md)
- Simple format fallback returns raw buffer without format parsing (mood/action not extracted)

### Future Considerations
- Make TEMPLATE_DIALOG configurable per-connector
- Add UI toggle for minimize_quality_prompt in connector settings
- Consider alternate dynamic environment positioning
- Improve simple format fallback to attempt basic format extraction
