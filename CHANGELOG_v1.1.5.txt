## Version 1.1.5 (2025-11-12) - CRITICAL HOTFIX

### Critical Bug Fix

**Simple Format Fallback Stripping First Character (CRITICAL)**
- **Problem**: Only first few characters appeared in-game ("ovely" instead of "lovely)")
- **Root Cause**: Fallback code tried to strip prefill from buffer, but prefill was never in buffer
- **Example Issue**:
  - LLM outputs: `lovely) : pauses in her organization...`
  - What appeared: `ovely`
  - Bug: `substr('lovely)...', 1)` incorrectly stripped first `l`
- **Fix**: Return `$this->_buffer` directly without stripping
- **Files**: `openrouterjsoncached.php` lines 1036-1054, `openrouterjsoncached_verbose.php` lines 1721-1752
- **Result**: Full messages now appear correctly

### Technical Details

**Buffer vs BufferToParse Explained**:
- `$this->_buffer`: Raw API response (e.g., `lovely) : pauses...`)
- `$bufferToParse`: Temporary with prefill for parsing (e.g., `(lovely) : pauses...`)
- **Key**: Prefill ONLY added to $bufferToParse, NEVER in $this->_buffer
- **v1.1.4 Bug**: Tried to strip prefill from buffer that never had it
- **v1.1.5 Fix**: Return buffer as-is without stripping

### Additional Improvements
- Reduced error logging spam (don't log on first chunk < 20 chars)
- Enhanced verbose logging showing prefill status
- Better code comments explaining buffer handling

### Files Modified
- `connector/openrouterjsoncached.php` - v1.1.4 → v1.1.5
- `connector/openrouterjsoncached_verbose.php` - v1.1.4 → v1.1.5

## Version 1.1.4 (2025-11-12) - CRITICAL FIXES

### Critical Bug Fixes

**Bug #1: Profile Section Settings Not Saving (CRITICAL)**
- **Problem**: Connector settings in Profiles editor silently discarded
- **Root Cause**: Used `metadata[...]` instead of `meta_vis[...]` field naming
- **Fix**: Renamed 13 fields in Profiles section
- **Files**: `ui/core/llm_connectors.php` lines 429-494
- **Result**: Profile section settings now save correctly

**Bug #2: Simple Format Not Working (CRITICAL)**
- **Problem**: Simple format responses received but never appeared in-game
- **Root Causes**:
  1. No fallback when parsing failed → empty string returned
  2. Regex required both parentheses → prefill case failed
  3. Regex didn't handle optional colons → some LLM outputs failed
- **Fixes** (from v1.0.20-22 Bug #6 & #8):
  1. Added fallback handling
  2. Made opening parenthesis optional: `\(?`
  3. Made colon optional: `:?\s*`
- **Files**: Main + verbose connectors, helpers
- **Result**: Simple format works with variations and fallback
- **Note**: v1.1.4 introduced substr() bug, fixed in v1.1.5

### Files Modified
